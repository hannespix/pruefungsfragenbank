# Coordinator-first examination workshop

The user cannot understand the current task-first navigation. The first authenticated
screen must be the competent authority's control centre, with a visible sequence:
prepare meeting, invite specialty groups, compose ZP/AP exams, review results.
Each specialty has one workspace with two clearly separated examination tracks.

Decision delegated by user: preserve GitHub Pages, the encrypted coordinator gate,
and existing editor. Build a meeting-first dashboard, not another task-bank landing
page. A separate app or a cosmetic navigation rename would duplicate work or leave
the central workflow unclear.

Meeting records persist in project JSON with title, target exam year, meeting date,
and selected specialties. Examination drafts may reference a meeting; AP and ZP
remain distinct. Meeting editing must not strand existing examination drafts.
Legacy projects remain importable. Old unassigned drafts remain visible in results.

The authority can prepare meetings, open each specialty workspace, configure its
patterns, compose several exams of either type, inspect progress and export the
paired candidate/solution output. The session-only Pages storage warning stays.

Groups & invitations is a first-class destination. Show each group's access status,
the intended QR/link location and the exact current blocker. No fabricated QR,
permanent shared-key link, client-only authentication or pretend session switch.
Actual invitations and examiner authentication require the not-yet-configured API.
The workspace available now is explicitly the authority's editing view, not a
security role switch. Never claim that the static coordinator prototype implements
examiner privileges or group isolation.
